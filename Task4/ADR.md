### **Решение**

#### Диаграммы C4

- **c4_context.drawio** — Диаграмма контекста (C4 Level 1): показывает новые потоки ставок к кол-центрам в контексте MVP-системы.
- **c4_components.drawio** — Диаграмма компонентов (C4 Level 3): детализация внутренних компонентов Deposit Integration Service и Системы кол-центра, ответственных за распределение ставок.

---

#### Ключевые архитектурные решения

**1. Ставки в систему кол-центра банка — через Rates REST API АБС**

В рамках MVP АБС уже получает новый Rates REST API endpoint (от команды АБС, Java-стек). Система кол-центра (Java Spring Boot) добавляет новый scheduled-компонент **Rates API Client**, который:
- По расписанию (ежедневно) вызывает Rates REST API АБС
- Сохраняет ставки в существующую PostgreSQL-базу системы кол-центра
- Новый UI-компонент (React.js) отображает ставки операторам

Обоснование: Система кол-центра уже на Java Spring Boot — scheduled job реализуется тривиально. Отдельный сервис не нужен. Rates REST API АБС — единый источник истины.

**2. Ставки для партнёрского кол-центра — SFTP-экспорт через Deposit Integration Service**

Партнёрский кол-центр работает во внешней системе без возможности API-вызовов. Единственный вариант — файловый обмен по SFTP. 

Deposit Integration Service (уже спроектированный в ADR Task 3) получает новый компонент **SFTP Export Job**, который:
- По расписанию (ежедневно) читает ставки из Oracle АБС (через существующее соединение)
- Формирует CSV-файл с актуальными ставками
- Передаёт файл по SFTP на сервер партнёра

Обоснование: Integration Service (.NET) уже имеет соединение с Oracle АБС → минимальная новая разработка. Kafka/event-driven недоступны для внешнего партнёра.

### **Альтернативы**

| Альтернатива | Причина отклонения |
|---|---|
| Прямые вызовы АБС из системы кол-центра в real-time | Увеличивает нагрузку на АБС; ставки меняются раз в день — daily sync достаточно |
| Push-уведомления из АБС в систему кол-центра (webhooks) | АБС (PL-SQL/Delphi) не имеет out-of-box механизма push; сложнее в реализации для MVP |
| Отдельный новый сервис для SFTP-экспорта | Излишний новый компонент: Deposit Integration Service уже подключён к Oracle АБС и является логичным местом для этой функции |
| Передача ставок партнёрскому КЦ по email (Excel) | Ручной процесс не масштабируется, подвержен человеческим ошибкам; SFTP автоматизирован |
| Kafka для передачи ставок в кол-центр | Текущая версия интернет-банка несовместима; для кол-центра достаточна daily синхронизация без Kafka |

**Недостатки, ограничения, риски**

| # | Описание |
|---|---|
| 1 | **Задержка обновления ставок.** Синхронизация происходит раз в сутки. Если ставки изменились в течение дня, операторы будут консультировать по устаревшим ставкам до следующей синхронизации. Приемлемо для MVP, т.к. ставки обновляются ежедневно утром. |
| 2 | **Зависимость от SFTP-сервера партнёра.** Если SFTP-сервер партнёра недоступен, файл не будет передан. Необходим retry-механизм и алертинг. |
| 3 | **Единая точка отказа — Rates REST API АБС.** Если АБС Rates API недоступен, и система кол-центра, и Integration Service не получат свежих ставок. Необходимо кэширование последних известных ставок. |
| 4 | **Безопасность SFTP.** Файл содержит бизнес-данные (ставки). Необходима ротация ключей SFTP и мониторинг доступа. |
